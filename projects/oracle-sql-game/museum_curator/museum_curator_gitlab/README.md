# Куратор музея

Лабораторная работа №2. Экономический симулятор: игрок руководит музеем —
открывает залы, покупает экспонаты, нанимает сотрудников и старается не
уйти в минус.

Главное требование работы: **вся игровая логика находится в базе данных**.
Расчёт посетителей, дохода, рейтинга, случайные события, зарплата, проверка
банкротства — всё это PL/SQL. Python не считает ничего, он только рисует
картинку и передаёт нажатия кнопок в пакет.

Выполнил: Сеидов Мирсамед Сеид-Азимович, группа КС-23-18.

## Из чего состоит

    sql/      вся логика игры
    python/   графический клиент и установщик схемы
    tools/    автоматические проверки проекта
    scripts/  сборка exe
    doc/      разбор логики и разбор кода (для защиты)

### sql

| файл | что внутри |
|---|---|
| `00_drop_all.sql` | очистка схемы перед установкой |
| `01_tables.sql` | 22 таблицы, последовательности, индексы |
| `02_reference_data.sql` | справочники: темы, должности, улучшения, сложности |
| `03_catalog_data.sql` | каталог из 20 экспонатов |
| `04_package_spec.sql` | спецификация пакета `museum_curator` |
| `05_package_body.sql` | тело пакета: 78 подпрограмм, вся логика |

### python

| файл | назначение |
|---|---|
| `main.py` | игра: экраны, диалоги, фоновый поток обращений к базе |
| `ui.py` | кнопки, поля ввода, всплывающие окна |
| `db.py` | тонкая обёртка над пакетом: вызвать процедуру, забрать курсор |
| `installer.py` | ставит схему: режет `.sql` на операторы и выполняет |
| `settings.py` | адрес базы и логин (пароль не сохраняется) |
| `resources.py` | поиск файлов и в исходниках, и внутри exe |
| `config.py` | цвета и размеры окна |

## Как запустить

### Из исходников

```powershell
python -m venv .venv
.\.venv\Scripts\pip install -r requirements.txt
.\.venv\Scripts\python.exe python\main.py
```

### Собрать exe

```powershell
.\scripts\build_exe.ps1
```

Получится один файл `dist\MuseumCurator.exe` (около 22 МБ). Внутри уже
лежат pygame, oracledb и все sql-скрипты, поэтому на учебный стенд надо
скопировать только его. Ни Python, ни Oracle Client ставить не нужно:
`oracledb` работает в тонком режиме.

### Подключение

При первом запуске игра спрашивает адрес сервера, порт, SID или имя
сервиса, пользователя и пароль. Всё, кроме пароля, запоминается в файле
`museum_connection.json` рядом с exe.

Если в схеме ещё нет таблиц, игра сама предложит их создать — кнопка
«Установить схему». Установка выполняет все шесть скриптов из `sql`
по порядку, около 100 операторов, занимает несколько секунд.

Требуется Oracle 12.2 или новее.

## Проверки

Без сервера Oracle:

```powershell
.\.venv\Scripts\python.exe tools\check_all.py
```

Восемь проверок: статический контроль кода, сверка ключей словарей в
клиенте с именами столбцов в SQL, сверка с каждым курсором пакета,
сверка кодов действий и аргументов, разбор скриптов установки, поиск
русских имён таблиц в SQL-строках, прогон всех экранов вслепую и
прогон граничных случаев (пустой музей, банкротство, обрыв связи).

Эти же проверки запускаются автоматически в GitLab CI, см.
`.gitlab-ci.yml`.

На живом сервере — целая партия через базу:

```powershell
.\.venv\Scripts\python.exe python\check_runtime.py 10.22.10.41 1521 sid orcl ЛОГИН ПАРОЛЬ
```

Скрипт проходит все девять действий куратора, крутит игровое время,
проверяет ускорение и закрытие дня, а в конце удаляет созданный тестовый
музей.

## Управление в игре

Всё делается мышью, но у каждой кнопки есть клавиша:

| клавиша | действие |
|---|---|
| `1` | открыть зал |
| `2` | купить экспонат |
| `3` | выставить в зал |
| `4` | убрать на склад |
| `5` | продать экспонат |
| `6` | нанять сотрудника |
| `7` | назначить в зал |
| `8` | улучшение зала |
| `9` | сменить тему зала |
| `Q` | состояние музея |
| `W` | статистика |
| `E` | справка |
| `S` | скорость времени: ×1 → ×2 → ×4 → ×8 |
| `P` | пауза и выход в меню |
| `F` | завершить партию |
